# 方案演進與決策

| 階段 | 驗證與取捨 |
| --- | --- |
| 4C 自建 RAG | 驗證向量建置、檢索、模型問答與來源核對。團隊接著借助 NotebookLM，加快指定來源問答的原型驗證。兩條路徑的檢索品質缺少同條件比較。 |
| 5A 與 6A NotebookLM 橋接 | 5A 在單機、單人、固定來源完成四輪真實問答，核對八段摘錄。6A 在同機以雙 Chrome 設定檔及雙帳號交錯測試，該次未觀察到串話，橋接仍記錄過引用擷取失敗與逾時。 |
| 6B 語氣調整 | 以合成回答驗證 Cloud Run／Vertex AI 整合。人工覆核發現說話角色改變、新增時間描述及遺漏步驟。 |
| 早期 7A1 語氣調整 | 使用真實 NotebookLM 原答完成改寫往返，人工發現引號內措辭變動。後續團隊移除語氣調整視窗，Cloud Run 服務停用。 |
| 7A1 至 7A2 | 延續單欄原答與可取得引用；在資源查詢加上團隊長照需求與費用指南。指南透過同站子頁開啟並提供返回入口。 |

依據為《4C 專案進度與分工》《5A 單人真實 Demo 驗收》《5A／6A／6B 專案狀態 跨機流程補充版》、11 月 11 日及 11 月 13 日 7A1 狀態紀錄與 7A2 審閱交接。
